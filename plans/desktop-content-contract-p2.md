# desktop-content-contract-p2 — unpersisted chat channel and agent/conversation gating

You are phase `p2` of the `desktop-content-contract` plan. This phase delivers, as one commit, the `reads_desktop_content` marker on actions and every mechanism that keeps a marked action's output and derived replies out of `chat_log`, `conversation_summaries`, the INFO/DEBUG logs, and the cloud research tools.

## Locked decisions
See the master `plans/desktop-content-contract.md`. The decisions binding this phase:
- Marked actions are excluded from the **conversation** path's tool specs, refused by its executor if named anyway, and included in the **agent** path's. Desktop content never enters `ConversationSession.history`.
- The unpersisted channel is `log_buddy_message(text, persist=False)`, exposed on `AbstractOverlay` and implemented by Qt and Textual. Bubbles are unchanged.
- An agent session that executed a marked action delivers its final text through the unpersisted channel and shows a persisted bubble written by the persona from a content-free prompt (operator direction 2026-09-02). Fallback when the persona line is filtered out or generation fails: the literal string `"Done. The answer is in the chat log and was not saved."`.
- After a marked action runs, tools whose catalog entry has a non-empty `consent_category` are dropped from the tool list for the rest of that run (`tokenpal/actions/catalog.py:26-29`, `find_entry` at `catalog.py:276-282`); one already requested in the same LLM response is not invoked and returns `"skipped: desktop content is in context"`.

## Decisions & findings
### Decision: redact in the runner, not in the tool  *(status: active)*
- **Rationale:** the runner owns the trace (`_log` calls at `agent.py:256,266`), the cache, and the tool list; putting the rules there means a tool author sets one ClassVar and gets all three. A tool that forgets the marker is caught by p3's registry test only if it declares the marker at all, so the docs (p3) make the marker the first line of the checklist.
- **Alternatives considered:** each tool returning a redacted `display_text` (leaves the 240-char trace preview in place); a wrapper `ActionResult` subclass (the runner still needs the tool list rule).
- **Evidence:** `tokenpal/brain/agent.py:243-300`.

### Decision: keep `AgentStep.result` unredacted in memory  *(status: active)*
- **Rationale:** the step result feeds the next prompt (`messages.append` at `agent.py:186-190`) and lives only in the process; `AgentSession` is never persisted (grep `AgentSession` in `tokenpal/brain/memory.py`: no hits at 1de1d43). Redacting it would break the agent's ability to use what it read.
- **Evidence:** `agent.py:33-39` caps, `orchestrator.py:1885-1890` consumes only `final_text` and the summary.

### Decision: persona bubble from a content-free prompt  *(status: active)*
- **Rationale:** the operator wants the buddy, not a canned sentence, to announce completion. Leak safety comes from what the prompt omits, not from asking the model to be careful: the template has no slot for content, goal, app, or trace, so the model cannot echo what it never saw.
- **Alternatives considered:** passing the goal so the line can reference the task (rejected: the goal is user-typed and may itself quote content); reusing `get_confused_quip` (rejected: canned, wrong meaning).
- **Evidence:** template pattern `personality.py:521-548,981-996`; one-shot generate + `filter_response` pattern `orchestrator.py:1389-1400`.

## Failure modes to anticipate
- `tests/test_ui_adapter_contract.py:26-45` calls `log_buddy_message` positionally with one argument; the new keyword must default to `True` so that contract and every existing caller are unchanged.
- `LogBuddyMessage` is a Textual `Message`; adding a constructor kwarg is safe, but `on_log_buddy_message` must forward it or Textual silently persists again. The Textual assertion is not covered by a Qt test; add a targeted test only if `tests/test_ui/` already constructs `TextualOverlay` without a running app (`tests/test_ui/test_divider.py:23` does), otherwise verify with `./run.sh --overlay textual` and note it in Status.
- Strict mypy on the `Protocol`: the risk is not `_agent_log` (extra defaulted keyword-only parameters on an implementation satisfy a Protocol) but the three lambda fallbacks named in Work; run mypy after widening `AgentBridge` and add `_noop_log` only if it complains.
- The tool-drop filter runs on `self._tool_specs`, which the orchestrator now builds as the full list for the agent. If a later change passes a pre-filtered list, the drop still works because it filters whatever it was given.
- One LLM response can carry several tool calls (`agent.py:177-200`), so the flag must be set per call inside the batch loop, not after it, or a network tool requested alongside the content read would run before the drop applies. Work covers this with the same-batch skip; test (5) pins it.
