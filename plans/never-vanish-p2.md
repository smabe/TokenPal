# never-vanish-p2 — own bundle identity on macOS, launched through LaunchServices

You are phase `p2` of the `never-vanish` plan. This phase gives the Qt overlay its own macOS identity: on macOS, `tokenpal` builds `~/.tokenpal/TokenPal.app` (bundle id `com.tokenpal.app`) around the Python framework stub and relaunches itself through `open`, so the menu bar item is attributed to TokenPal and never to the terminal that started it. One commit.

## Locked decisions
See the master `plans/never-vanish.md`. The decisions binding this phase:
- Bundle id `com.tokenpal.app`, bundle name `TokenPal`, location `<data_dir>/TokenPal.app` (data dir resolved at `tokenpal/app.py:143`; default `~/.tokenpal`, `tokenpal/config/schema.py:229`). Constant across venv rebuilds and Homebrew upgrades — Control Center keys its records on the Info.plist id alone: a copied stub whose code signature still says `org.python.python` was placed at `(1487, 7)` under its own Info.plist id (probe 2026-09-06). No re-signing step.
- The relaunch decision lives in `tokenpal.app:main`, after the first-run wizard and before `discover_senses`, so every entry point (`run.sh:47`, `scripts/install-macos.sh:656`, bare `tokenpal`) is covered and the wizard still runs in the terminal with stdin. `--check`, `--validate`, `--version` never relaunch (they exit before the decision point, `tokenpal/app.py:138-152`).
- Only the Qt overlay relaunches: darwin, resolved overlay name `qt`, and not already inside the bundle. Textual/console/`TOKENPAL_HEADLESS=1` (`tokenpal/ui/registry.py:_qt_unavailable_reason`, `:21`) stay in-process.
- Launch is `open -W --env TOKENPAL_LAUNCH_CWD=<parent cwd> --stdout <T1> --stderr <T2> <bundle> --args -m tokenpal <original argv> --skip-welcome`. `<Tn>` is `os.ttyname(n)` when `os.isatty(n)` (per fd — stdout and stderr decided separately), else `<data_dir>/logs/tokenpal-bundle.log`, which the parent truncates before launching. No `-n`: one instance. The already-running check runs **before** `ensure_bundle`, so a rebuild can never `rmtree` a live app's tree.
- Ctrl-C in the terminal quits the buddy through the app's existing shutdown path: the parent runs `open` with `subprocess.Popen`, catches `KeyboardInterrupt`, sends `SIGINT` to `processIdentifier()` of every `NSRunningApplication.runningApplicationsWithBundleIdentifier_(BUNDLE_ID)` (so `_shutdown` at `tokenpal/app.py:1826-1830` schedules `overlay.teardown()` and the persist flush as today), polls `isTerminated()` up to 5 s, then `forceTerminate()`, then waits for `open`. `subprocess.run` is not used — it SIGKILLs `open` inside its own `KeyboardInterrupt` handling before ours runs.
- The child restores the parent's working directory: `main()` begins with `if cwd := os.environ.get("TOKENPAL_LAUNCH_CWD"): os.chdir(cwd)` before `load_config`, so the repo-local `config.toml` fallback (`tokenpal/config/paths.py:22-25`, `tokenpal/config/loader.py:133`), `git_root(Path.cwd())` for `find_files`/`open_path` (`tokenpal/util/paths.py:62,177-178`), `grep_codebase` (`tokenpal/actions/grep_codebase.py:154`) and `git_log` (`tokenpal/actions/git_log.py:20`) see the same cwd as a terminal run. `--config` needs no rewrite because of this.
- Venv discovery inside the bundle uses `Contents/pyvenv.cfg` + `Contents/lib/python3.X/site-packages` → venv purelib symlink (probe: PySide6 6.11.0 and editable `tokenpal` import this way, also under a path with spaces; the `__PYVENV_LAUNCHER__` env alternative is rejected because it makes the bundle depend on its launcher's environment).
- Fallback: if the framework stub does not exist (non-framework Python: uv-managed, pyenv without `--enable-framework`), if building raises `OSError`, or if `open` returns non-zero, log one warning naming the reason and continue in-process exactly as today. `relaunch_in_bundle` raises `RuntimeError` on a non-zero `open` return so the same `except` covers it. Never crash on the bundle path.
- Under the bundle, `responsible_host()` returns `"TokenPal"`. The bundle check precedes the `TERM_PROGRAM` read because `open` passes the shell's environment through.

## Decisions & findings
### Decision: relaunch in `app.main`, not in `run.sh`  *(status: active)*
- **Rationale:** three launchers converge on `main()` (`run.sh:47`, `scripts/install-macos.sh:656`, the `tokenpal` console script `pyproject.toml:87`); the wizard needs the terminal's stdin and runs before the decision; the fallback logic needs Python.
- **Alternatives considered:** `open` from `run.sh` — leaves bare `tokenpal` and the installer on the shared identity; `NSWorkspace.openApplicationAtURL:` — returns the `NSRunningApplication` directly but has no stdout redirect, so `./run.sh --verbose` would lose its terminal output.
- **Evidence:** `tokenpal/app.py:135-239`; `open` probes 2026-09-06 (master Background findings).

### Decision: copy the framework stub instead of symlinking it  *(status: active)*
- **Rationale:** both work (specialist probe), but a copy survives a Homebrew upgrade that removes the old Cellar path until the stamp triggers a rebuild, instead of a dangling symlink that fails at `open` time.
- **Evidence:** `otool -l` shows absolute `LC_LOAD_DYLIB` to the Cellar path, so the copy loads the same framework.

### Decision: Ctrl-C forwards SIGINT, not `terminate()`  *(status: active)*
- **Rationale:** `terminate()` delivers a Quit Apple event that Qt turns into `app.quit()`, bypassing `_shutdown` (`tokenpal/app.py:1826-1830`) which is the only path that runs `overlay.teardown()` → `flush_pending_persist()` (`tokenpal/ui/qt/overlay.py:1040-1050`). SIGINT to the child's pid keeps that path intact.
- **Evidence:** historical reviewer 2026-09-06 (commits `1e3acde`, `e9e5f60`, `3484a06`); `subprocess.run` kill-on-exception in CPython's `subprocess.py`.

### Finding: `open -W` semantics (probed 2026-09-06)
- Returns 0 even when the child exits non-zero; prints "Unable to block on applications" and returns 1 if the child exits before `open` attaches (sub-second). SIGINT to `open` kills nothing. `--stdout` must be a real path; `/dev/fd/1` fails with `-10810`. `--env` is delivered to the child.

### Finding: Control Center keys on the Info.plist id (probed 2026-09-06)
- A byte copy of the Python.app stub inside `StubPlain.app` (Info.plist id `com.tokenpal.probe.stubplain`, `codesign -dv` still `Identifier=org.python.python`) launched with `open` was placed at `(1487, 7)` and painted; `NSBundle.mainBundle().bundleIdentifier()` reported the Info.plist id and `sys.prefix` the bundle's `Contents`. `codesign --force` on the bundle fails ("In subcomponent: …/Contents/pyvenv.cfg"), so signing is neither needed nor easy.

### Decision: build the bundle into a sibling temp directory and `os.replace` it into place  *(status: active — carried in from p1's review)*
- **Rationale:** the shard's `ensure_bundle` as drafted does `shutil.rmtree` + recreate-in-place, with a stamp file written last so a bad prior build is detected. If the process dies between the `rmtree` and the stamp — crash, force quit, OOM — `TokenPal.app` is left half-built with no stamp, and the next `relaunch_in_bundle` hands that broken bundle to `open`. The repo already solves exactly this three times over and never in-place: `tokenpal/config/toml_writer.py:37-39` (`tmp = path.with_suffix(".tmp")` → `os.replace`), `tokenpal/server/job_store.py:50-54` (`tempfile.mkstemp` → `os.replace`), `tokenpal/audio/deps.py:180-186` (`dest.tmp` → `tmp.replace(dest)`). Build into a sibling temp directory, then `os.replace` it over the old bundle; keep the stamp as the *content* identity check (Python version, cdhash) it is needed for, not as partial-build recovery.
- **Evidence:** p1 review round 1, reuse angle, 2026-09-06; the three call sites above read this session.
- **Note for the worker:** `os.replace` on a directory requires the destination to be an empty directory or absent — rename the old bundle aside and delete it after the swap, or remove it immediately before the rename and accept a much smaller window than the current design's.

## Failure modes to anticipate
- **Permissions re-grant, and it recurs.** First run after this phase, macOS prompts for Screen Recording (and Accessibility / Microphone if used) for "TokenPal"; Screen Recording takes effect only after the app restarts. TCC's requirement for an ad-hoc-signed binary is bound to its cdhash, so every stub rebuild (Homebrew Python upgrade, Python minor bump) invalidates the grant and the prompt returns. Expected; the `--validate` wording is the mitigation.
- **Non-framework Python** (uv-managed, pyenv without `--enable-framework`): `framework_stub()` is None → in-process fallback with a warning. The three non-Mac target machines are unaffected (darwin gate).
- **Stub path churn**: Homebrew minor upgrades change the Cellar path; the stamp includes the resolved stub path and mtime → rebuild. A Python minor bump changes `lib/python3.X` → rebuild by the version in the stamp.
- **Environment through `open`**: PATH/HOME/TERM/TERM_PROGRAM are inherited (probe); cwd is restored by the child from `TOKENPAL_LAUNCH_CWD`.
- **Workers spawned with `sys.executable`** (`tokenpal/audio/backends/kokoro.py:67`, `tokenpal/audio/deps.py:99`) now run the bundle stub; they inherit `pyvenv.cfg` discovery through the bundle and create no status item. Nothing to change; verify with `tokenpal --check` inside the bundle if audio is enabled.
- **Log file redirect**: only non-tty launches hit `tokenpal-bundle.log`; the parent truncates it per launch, so it never grows across runs (whether `open` itself truncates is unverified — `man open` does not say).
- **Never test the tray from a Claude Code shell on the operator's Mac.** The AX/placement Done criterion is run from a Ghostty window (`open -na Ghostty.app --args -e <repo>/run.sh`). A unit test that `show()`s a real `QSystemTrayIcon` from pytest run in that shell poisons the registry; none may exist (today's suite constructs `BuddyTrayIcon` in `setup()` but only `run_loop` calls `show()`, `overlay.py:596`).
- `app.py` is a 122-commit file; keep the relaunch block to the one insertion point above and do not reorder the memory/sense setup that follows it.
