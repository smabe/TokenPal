## Goal
Let the user select text in another app, switch to TokenPal, type `/proofread` or `/explain`, and get the result in the chat pane, read through the macOS Accessibility API of the app they came from; both commands also take inline text; the same read is exposed to `/agent` as `read_selection`, the first `reads_desktop_content` tool.

## Scope contract
- **Requested outcome:** The user selects text in another app, switches to TokenPal, types `/proofread` or `/explain`, and gets the correction or explanation in the chat pane, read through the OS accessibility API of the app they came from (macOS first); both commands also accept inline text (`/proofread <text>`) which skips the OS read; `read_selection` is exposed to `/agent` as the first `reads_desktop_content` action.
- **Named semantic boundary:** the path selected text takes from another app's focused element into an LLM prompt and back to the chat pane, under #51's prompt-only contract (never memory.db, never logs, refused for sensitive apps, explicit command only).
- **Explicit inclusions:** a primitive under `tokenpal/desktop/` (macOS Accessibility read; selected text with a whole-field fallback capped near 8 KB and flagged as truncated; distinct errors for permission-missing vs app-refuses vs nothing-focused; an "unsupported" result on other platforms); `/proofread` and `/explain` slash commands with optional inline text; a `read_selection` action under #51's marker with a catalog entry; tests with a fake accessibility layer and the scripted LLM; ruff + mypy clean.
- **Explicit exclusions:** writing corrections back into the source app; screenshot/OCR fallback (#55); Linux AT-SPI; ambient/idle reads; clipboard reading; the Windows UI Automation implementation (the issue calls it phase 2, and the author-on-target-host rule requires it be written on the Windows box).
- **Intent class:** bounded outcome

## Non-goals
- **No Windows implementation.** `read_selection` declares `platforms = ("darwin",)`; on Windows and Linux the primitive returns the "unsupported" failure and the inline-text form of both commands still works. The Windows UI Automation path is filed as a follow-up at ship (see Parking lot). Windows `--validate` row from #51 stays carried.
- **No clipboard write helper.** Issue #52 lists `copy_to_clipboard` as optional and says the user copies from the chat pane otherwise; clipboard reads stay rejected (CLAUDE.md Privacy). Surfaced at approval.
- **No Chromium/Electron workaround.** Chromium-based apps (Chrome, Edge, VS Code, Slack, Orca) return `kAXErrorNoValue` for their focused element while inactive, and setting `AXEnhancedUserInterface`/`AXManualAccessibility` on the app element did not change that for an inactive window (probe 2026-09-03, Background findings). The read reports "nothing focused" with a hint to use the inline form. Electron's `AXEnhancedUserInterface` also has documented window-positioning side effects (Parking lot).
- **No whole-field range read.** `AXStringForRange` + `AXNumberOfCharacters` would bound the copy to the cap before it leaves the target process; this plan reads `kAXValueAttribute` and truncates in-process. The text never persists either way, and the range read adds a second attribute protocol for no contract gain.
- **No console/tkinter delivery.** `AbstractOverlay.log_buddy_message` is a no-op there (`tokenpal/ui/base.py:68-80`), so an unpersisted reply has nowhere to go; `docs/claude/actions.md` already states marked tools assume a chat log. The same holds for the agent path shipped in #51.
- **No change to `_MESSAGE_RESULT_CAP` or `_truncate`** (`tokenpal/brain/agent.py:37`, `:405-406`). The runner cuts a tool result at 2,048 chars, which would drop the envelope's closing tag; the tool caps its own text instead (p2 locked decision) and the author checklist gains that rule.
- **No `consent_category` on `read_selection`'s catalog entry.** `_needs_consent` (`tokenpal/brain/agent.py:383-387`) treats any non-empty category as "reaches the network" and `_tools_for` (`:291-303`) drops such tools after a content read, so a category would drop the tool after its own first read.
- **No debounce on the two commands.** `/ask` and `/gh` have none either (`tokenpal/app.py:967-1067`); the brain drains the desktop-task queue in order and each request produces its own status line.
- **No Chromium-specific error text.** The reader cannot tell a Chromium app from a Cocoa app that has no focused text; one message covers both.

## Background findings
Research 2026-09-03 at 813f8c7.

- **Accessibility API via pyobjc.** `HIServices.AXUIElementCopyAttributeValue(el, attr, None)` returns `(err, value)` (pyobjc metadata marks the third argument as an out pointer; probed). Error constants, exported identically by `HIServices` and `ApplicationServices`: `kAXErrorAPIDisabled` -25211, `kAXErrorCannotComplete` -25204, `kAXErrorNoValue` -25212, `kAXErrorAttributeUnsupported` -25205, `kAXErrorInvalidUIElement` -25202, `kAXErrorNotImplemented` -25208 (SDK `HIServices.framework/Headers/AXError.h:43-73`; per-call meanings `AXUIElement.h:133-147`). `kAXWebAreaRole`, `AXEnhancedUserInterface`, `AXManualAccessibility` are not bound — string literals only.
- **Messaging timeout.** `AXUIElementSetMessagingTimeout(el, seconds)`: on the system-wide element it sets the process-global default; on any other element only that element; 0 resets (`AXUIElement.h:386-402`). Apple documents no default value (`:392` says one exists). Probe against a `SIGSTOP`ped Cocoa app (this Mac, not reproducible by an auditor): `kAXErrorCannotComplete` after exactly the set timeout (0.3/0.5/2.0/5.0 s measured); unset default measured 1.5 s. Because the setting is per element, the reader sets it on the application element and again on the focused element it reads from.
- **Attributes and roles.** `kAXSelectedTextAttribute` is "required for all editable text elements" (`AXAttributeConstants.h:683-694`); `kAXValueAttribute` is the whole-field value (`:342`). Probe: `AXTextField`/`AXTextArea` answer both; `AXStaticText`, `AXOutline`, `AXWindow` return -25205 for both. `kAXSecureTextFieldSubrole` is defined at `AXRoleConstants.h:408`; Apple's web reference describes it as a text field intended to contain sensitive data. Probe: its `AXValue` is bullets (U+F79A), `AXSelectedText` is -25205. No other sensitivity marker exists in the headers.
- **Inactive apps.** Cocoa apps (Finder, Sublime Text, TextEdit-class) answer `kAXFocusedUIElementAttribute` while inactive. Chromium/Electron apps (Microsoft Edge, Orca, Signal) return -25212 while inactive; Edge returned -25212 even while active until an AX client set `AXEnhancedUserInterface` (Chromium debounces that 2 s, `chrome/browser/chrome_browser_application_mac.mm:416-459`; Electron adds `AXManualAccessibility`, `shell/browser/mac/electron_application.mm:221-264`), and after enabling, inactive windows still returned -25212 because Chromium's focus tracking drops on deactivation (`render_widget_host_view_cocoa.mm:2316`). Probed on this Mac 2026-09-03.
- **Window order.** `kCGWindowListOptionOnScreenOnly`: "Windows are returned in order from front to back" (Apple, `coregraphics/cgwindowlistoption/optiononscreenonly`). Each dict carries `kCGWindowOwnerPID` and `kCGWindowOwnerName`; the app-awareness sense already iterates it on the brain thread (`tokenpal/senses/app_awareness/macos_apps.py:41-68`). Under the Qt overlay the frontmost layer-0 owner when the user types a command is TokenPal's own process (the chat window is focusable, `tokenpal/ui/qt/_log_window.py:58`, `activateWindow` at `tokenpal/ui/qt/overlay.py:1341`); under Textual it is the terminal app. Probe 2026-09-03 from this session (host Orca, while the operator was working in Edge): first layer-0 owners were `Microsoft Edge`, `Orca`, `Finder`, … — the host was second because another app was frontmost, which is the probe's condition, not the command's: when the user types `/proofread` the host holds keyboard focus and is frontmost. Orca's pid is not in this process's ancestor chain (`Orca Helper` is), so ancestor-walking cannot identify the host; the front-to-back order can. p1's live check confirms the rule with the Qt overlay.
- **Trust.** `AXIsProcessTrusted` reports whether the current process is a trusted client (`AXUIElement.h:68-74`); untrusted reads return `kAXErrorAPIDisabled` (header comment; unverified here, grant present). The grant attaches to the *responsible* process: under a terminal that is the terminal app, which is why `tokenpal/cli.py:249-256` names `TERM_PROGRAM`.
- **Sinks.** Every speech bubble is persisted: Qt `_do_show_bubble` ends in `_do_log(..., persist=True)` (`tokenpal/ui/qt/overlay.py:1192`); Textual `on_show_speech` calls `_log_buddy(text)` with `persist=True` (`tokenpal/ui/textual_overlay.py:1425-1426`). `CommandResult.message` becomes a bubble (`tokenpal/app.py:1736-1739`, `:2830-2833`). `log_buddy_message(..., persist=False)` skips the persist callback on both overlays (`qt/overlay.py:1207-1210`, `textual_overlay.py:1397-1399`) and emits no log line; TTS is reached only from the brain's reply and ambient paths, never from an overlay. The log file handler is always DEBUG (`tokenpal/util/logging.py:34,42`). `tokenpal/llm/http_backend.py:448` logs raw tool-call arguments at WARNING on a JSON parse failure; no other line in that file logs request or reply content.
- **Runner truncation.** `_MESSAGE_RESULT_CAP = 2048` (`tokenpal/brain/agent.py:37`) is applied to every tool result before it enters `messages` (`:244`) via `_truncate` (`:405-406`), which keeps `n-1` chars plus "…". An envelope longer than that loses its closing tag.
- **Threads.** Slash handlers run on the overlay's UI thread (Qt `tokenpal/ui/qt/overlay.py:1280-1284`; Textual `textual_overlay.py:1287-1295`). Work reaches the brain loop via `_post_threadsafe` (`tokenpal/brain/orchestrator.py:1796-1809`); queues are drained in order user-input → agent → research → refine → followup inside one tick (`:728-763`), each handler awaited inline, then `asyncio.sleep(poll_interval)` (2 s default). An in-flight agent or research run blocks every other queue until it returns. The sensitive-app check runs at handling time, not enqueue (`:2528-2537`, `:1868-1870`). `Quartz` already runs on the brain thread every poll (`macos_apps.py:41-55`); the only recorded thread gotcha is `NSWorkspace` (`:47-49`), which this plan does not use.
- **Conversation history.** `submit_user_input` lands in the conversation path, which appends to `ConversationSession.history` (`orchestrator.py:2549`, `:2625`) and feeds the summarizer (`:970-983`) and the INFO reply log (`:2626`). The no-history one-shot precedents are `_desktop_done_line` (`:1939-1952`) and `_emit_eod_bubble` (`:586-601`); the flagged agent branch delivers `log_callback(final, persist=False)` then a persona bubble (`:1925-1928`).
- **max_tokens.** Resolution order explicit → pin → latency-derived (floored by `min_tokens`, capped at `ctx//4`) → static default (`http_backend.py:202-236`). Budgets: `TargetLatencyConfig.tools = 8.0`, `freeform = 6.0` (`tokenpal/config/schema.py:79-90`). Research passes explicit fixed caps (`tokenpal/brain/research.py:446` = 400, `:725-726` = 1800/700/4000) and the conversation path passes `_effective_conv_max_tokens` (`orchestrator.py:1685`); nothing scales a cap on input length today.
- **Registry.** `register_action` keys on `action_name` (`tokenpal/actions/registry.py:18-21`); `discover_actions` swallows `ImportError` (`:33-34`); non-`DEFAULT_TOOLS` need `[tools] enabled_tools` (`:56-63`); `platforms` gate at `:65`. `_MARKED` in the contract test is built at import (`tests/test_desktop/test_privacy_contract.py:35-39`), `_instantiate` skips on any constructor exception (`:239-243`), registry/catalog parity is `test_every_registered_action_has_a_catalog_entry` (`:304-310`), the envelope-literal scan is `:336-358`. The contract's network walk from `tokenpal.desktop.content` reaches no network module (run this session against the walker: `content reaches network: False`), so a marked tool whose closure adds only `tokenpal.desktop.selected_text` (stdlib + deferred pyobjc) passes `test_marked_action_reaches_no_network_client`.
- **Test harness.** `tests/test_brain/test_tool_loop.py:344-358` (`_ReadsAction`), `:412-431` (`_agent_brain`: `AgentBridge` with a capturing log that persists only `persist=True` lines into a real `MemoryStore`), `:434-476` (the no-leak agent run) are the shape p2 and p3 reuse. `tests/_helpers.py:22-73` (`ScriptedLLM`), `:100-145` (`capture_logs`, `assert_no_leak`).
